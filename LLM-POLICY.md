LLM policy
==========
stde.pegen's maintainers have limited time to review contributions (PRs, issues) and GitHub Discussions. Please respect their time by following the AI policy - a first violation will result in your issue/PR/discussion ggetting closed, and a second violation will result in a ban (GitHub only provides permanent bans). Due to having no contributions so far, the policy is not mature and may change in the future.

"Only yourself" exemption
-------------------------
If you are the only person who see the AI output, the situation is exempt from the policy. This includes if you never put the result code into a PR against stde.pegen, or copy-paste AI output as a PR description, commit message or issue message.

If you're not sure if you'll later want to contribute your code back to stde.pegen, I's suggest that you follow the policy.

Referring
---------
Linking to or naming an AI-assisted codebase is ok: you can say "I have / someone else has an AI-assisted repo that does xxx, and it's here if you want to take a look at it".

Code (including documentation)
------------------------------
- Tests must not be written by AI, except *trivial* modifications, which must be done with caution.
- Documentation and docstrings must not be written by AI, as AI-generated docs are known to be shallow or "off" in some way. Comments or files that serve as design notes or usage notes (e.g. "indended to be consumed by class `TwelfthSilver` only") have the same requirement.
  - The AI may generate placeholder docstrings, which you must either delete (if their content is very obvious) or replace with hand-written ones.
- You must commit yourself. However, it is OK to ask AI to do checks before you commit.
- Commit messages must not be AI-generated. Write them yourself.
  - It is encouraged, but not neccessary, to add a `Co-authored-by` bot annotation in the commit message if AI wrote most of the commit or some file(s).
- Other than these restrictions, there aren't restrictions on "how much code can AI write" yet. But that is only because I have yet to run into an issue on my repo; in the meantime, make sure
  - you understand the code and can really own them yourself, instead of only AI knowing how it wrote it
  - your usage of AI does not compromise the quality of your contribution
  - you are able to explain why your code is written this way, not some other way

Modifications are *trivial* if there is no other way to write them, or the other ways to write them are nearly identical. Examples include
- repetitive boilerplate (like the recurring `@pytest.mark.parametrize` (not including decorator arguments(?)) and `grammar = dedent("""...""")` (not including the triple string contents) in test files)
- typo fixes
- changing a word to synonym

When you do AI-generate these modifications, make sure you understand the code and can really "own them yourself" instead of only AI being able to justify the code. Otherwise, this will place a maintainability hazard on you (and us!). (Borrowed from [Rust's LLM policy](https://forge.rust-lang.org/policies/llm-usage.html).)

Non-coding
----------
It is OK to ask AI to explain, check a piece of code, or search (whatever that means: text based, vector-based, symbol graph based...) for something. However, AI may produce suboptimal output; you can open a GitHub Discussion to ask me to explain (whether you've tried AI or not)! In particular, there are quite a few rough edges in the code, and AI may try to make sense of something when it does not make sense (and is only that way because I don't have time).

You must not pretend that some AI-generated text is written by yourself.

You must disclose the level of LLM usage in your PR description. *Hiding LLM usage is not allowed.* Good example: "I noticed the test `test_bananas_are_sweet` failed when making the feature, and asked AI to explain the failure output. I fixed the bug myself, and added a helper function `bababa` which is generated by AI then edited." Bad example: a mere "Generated by Claude Code" or `Co-authored-by: SomeAICodingTool <noreply@someaicodingtool.com>`
- However, we would prefer it if you be transparent and leave the AI tool's `Co-authored-by` in the commit message.

Issue descriptions and PR descriptions must not be written by AI. Replying in an issue/PR with an AI-generated reply is not allowed.

It is ok to include some AI output for reference reasons (e.g. quoting), but you must clearly state that the quoted content is AI-generated.

Using an LLM as a "review bot" for PRs is not allowed.

### A note about natural language translations
I speak English and Chinese. Everyone can communicate with me (currently the sole dev), but using LLM to translate text for communication purposes is not allowed. Please using a more mechanical translator like Bing/Google Translate.

### Autonomous LLM agents
Autonomous LLM agents are NOT ALLOWED to interact with this repo. Violation of this rule will cause all the relevant accounts to be banned from this repo.
